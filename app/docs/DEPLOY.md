# Бесплатное демо в интернете: Render + Neon

Приложение запускается на **Render** (бесплатный веб-сервис в Docker), а база
данных живёт в **Neon** (бесплатный PostgreSQL). Базу Render мы не берём:
бесплатная база Render удаляется через 30 дней, а в Neon бесплатная база не
истекает.

Что для этого уже лежит в репозитории:

| Файл                | Зачем                                                                          |
| ------------------- | ------------------------------------------------------------------------------ |
| `render.yaml`       | описание сервиса для Render (Blueprint): Docker, бесплатный план, папка `app`  |
| `app/Dockerfile`    | сборка: Node собирает интерфейс, затем образ с PHP 8.4 и `pdo_pgsql`           |
| `app/.dockerignore` | что не копировать в образ (`node_modules`, `.env`, тесты)                      |
| `app/start.sh`      | при запуске: миграции → демо-аккаунт → `php -S` на порту, который даёт Render  |

Пароль от базы ни в одном файле не хранится: его вводят в настройках Render.

## Шаг 1. База в Neon

1. Зайдите на https://neon.tech и зарегистрируйтесь (можно через GitHub).
2. Создайте проект: **Create project**.
   - Name: `vinland`
   - Postgres version: 17
   - Region: **AWS Europe Central 1 (Frankfurt)** — тот же регион, что у сервиса в `render.yaml`.
3. На странице проекта нажмите **Connect**. Выключите переключатель
   **Connection pooling** (нужно прямое подключение) и скопируйте строку
   подключения. Она выглядит так:

   ```
   postgresql://neondb_owner:ПАРОЛЬ@ep-что-то.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
   ```

   Это и есть `DATABASE_URL`. В ней пароль — никуда её не коммитьте.

Таблицы создавать вручную не нужно: их создаст `start.sh` при первом запуске.

## Шаг 2. Сервис в Render

1. Убедитесь, что код с `render.yaml` уже отправлен на GitHub
   (в ту ветку, которую будете разворачивать).
2. Зайдите на https://render.com и зарегистрируйтесь через GitHub.
3. **New +** → **Blueprint** → выберите репозиторий (если его нет в списке —
   **Configure account** и дайте Render доступ к нему). Выберите ветку.
4. Render прочитает `render.yaml` и покажет сервис `vinland`. Он попросит
   значение для `DATABASE_URL` — вставьте строку из Neon.
5. Нажмите **Deploy Blueprint** (или **Apply**).
6. Подождите. Первая сборка идёт 5–10 минут: ставятся пакеты Node, собирается
   интерфейс, собирается PHP-расширение. Ход сборки видно во вкладке **Logs**.
   Успех выглядит так:

   ```
   Applied 001-schema.sql
   ...
   Demo account: demo@vinland.local / VinlandDemo2026
   PHP 8.4... Development Server (http://0.0.0.0:10000) started
   ```

7. Откройте адрес сервиса вида `https://vinland-xxxx.onrender.com` (он указан
   вверху страницы сервиса) и войдите:
   - email: `demo@vinland.local`
   - пароль: `VinlandDemo2026`

После этого каждый `git push` в эту ветку пересобирает и перезапускает сайт сам.

## Что значит «бесплатный план»

- **Сервис засыпает**, если 15 минут никто не заходил. Следующее открытие
  будит его, и это занимает **около минуты** — Render в это время показывает
  страницу загрузки. Перед показом преподавателю откройте сайт заранее.
- Бесплатных часов хватает, чтобы сайт работал весь месяц (750 часов).
- Neon тоже «засыпает» после 5 минут без запросов, но просыпается
  за долю секунды — этого не видно.
- В бесплатной базе Neon 0,5 ГБ — для демо этого с большим запасом.

## Как устроен запуск

- **Миграции.** `php database/migrate.php` выполняет только новые файлы
  `database/*.sql`, поэтому каждый перезапуск безопасен.
- **Демо-аккаунт.** В `render.yaml` стоит `RESET_DEMO=1`: при каждом запуске
  (а значит, и после каждого «засыпания») демо-аккаунт создаётся заново с
  данными за последние три недели. Всё, что посетители изменили в демо,
  сбрасывается — для показа это удобно. Другие зарегистрированные пользователи
  не трогаются. Если сбрасывать не нужно, поменяйте `RESET_DEMO` на `0` в
  **Environment**: тогда демо создаётся только один раз, если его ещё нет.
- **HTTPS и сессия.** HTTPS обеспечивает Render. Cookie сессии отправляется
  с флагом `Secure` (`SESSION_SECURE=1`), браузер видит сайт по `https://`,
  поэтому вход работает.
- **Лимит попыток входа.** Перед приложением у Render стоит прокси, и
  `REMOTE_ADDR` у всех запросов одинаковый. Поэтому включён `TRUST_PROXY=1`:
  адрес посетителя берётся из заголовка `X-Forwarded-For`. Локально этот
  флаг не нужен.
- **Веб-сервер.** Используется встроенный сервер PHP (`php -S`) в 4 процесса
  (`PHP_CLI_SERVER_WORKERS=4`) — тот же, что и при локальном запуске. Для
  учебного демо этого достаточно; для настоящей нагрузки нужен nginx или Apache.
- **Настройки базы.** `backend/database.php` берёт `DATABASE_URL`, если она
  задана, иначе — `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`
  из окружения или `.env`, как раньше.

## Если что-то пошло не так

- **Сборка пишет, что не найден Dockerfile.** Откройте сервис → **Settings** →
  **Build & Deploy** и проверьте: Root Directory = `app`, Dockerfile Path =
  `./Dockerfile` (или `app/Dockerfile`, если Render считает путь от корня репозитория).
- **В логах ошибка подключения к базе.** Проверьте `DATABASE_URL` в
  **Environment**: строка целиком, с `?sslmode=require` на конце, без пробелов.
- **«Слишком много попыток» при входе в демо.** Кто-то 5 раз подряд ввёл
  неверный пароль от демо-аккаунта. Это защита от перебора: подождите 15 минут.
- **Нужен администратор.** На бесплатном плане нет консоли Render, но команду
  можно выполнить со своего компьютера, подключившись к той же базе Neon:

  ```powershell
  $env:DATABASE_URL = 'строка подключения из Neon'
  php database/create-admin.php admin@example.com "пароль-от-10-символов"
  ```

## Проверить Docker-образ у себя (необязательно)

```bash
cd app
docker build -t vinland .
docker run --rm -p 8080:8080 -e DATABASE_URL='строка из Neon' vinland
```

Откройте http://localhost:8080. Если вход не сохраняется (cookie помечена
`Secure`, а здесь нет HTTPS), добавьте к команде `-e SESSION_SECURE=0`.
