# Бесплатное демо в интернете: Render + Aiven

Приложение запускается на **Render** (бесплатный веб-сервис в Docker), а база
данных живёт в **Aiven** (бесплатный MySQL 8). Это обычный MySQL, такой же,
как на своём компьютере. Бесплатная база Aiven не удаляется по сроку, карта
для регистрации не нужна.

Что для этого уже лежит в репозитории:

| Файл                | Зачем                                                                         |
| ------------------- | ----------------------------------------------------------------------------- |
| `render.yaml`       | описание сервиса для Render (Blueprint): Docker, бесплатный план, папка `app` |
| `app/Dockerfile`    | сборка: Node собирает интерфейс, затем образ с PHP 8.4 и `pdo_mysql`          |
| `app/.dockerignore` | что не копировать в образ (`node_modules`, `.env`, тесты)                     |
| `app/start.sh`      | при запуске: миграции → демо-аккаунт → `php -S` на порту, который даёт Render |

Пароль от базы ни в одном файле не хранится: его вводят в настройках Render.

## Шаг 1. База в Aiven

1. Зайдите на https://console.aiven.io/signup и зарегистрируйтесь (можно
   через GitHub или Google).
2. В проекте откройте **Services** → **Create service** → **MySQL**.
3. Выберите тариф **Free**. Облако и регион для бесплатной базы Aiven
   выбирает сам. Имя сервиса — например, `vinland-db`. Нажмите
   **Create service**.
4. Подождите, пока статус сменится с **Rebuilding** на **Running**
   (несколько минут).
5. На странице сервиса (**Overview**) есть блок **Connection information**.
   Оттуда нужны две вещи:
   - **Service URI** — строка вида

     ```
     mysql://avnadmin:ПАРОЛЬ@mysql-vinland-db-xxxx.aivencloud.com:12345/defaultdb?ssl-mode=REQUIRED
     ```

     Скопируйте её кнопкой копирования рядом (пароль в ней уже есть). Это и
     есть `DATABASE_URL`. Если удобнее по частям: Host, Port, User
     (`avnadmin`), Password и Database name (`defaultdb`) показаны там же —
     из них собирается такая же строка.

   - **CA certificate** — нажмите **Download** (или значок скачивания), получится
     файл `ca.pem`. Это сертификат, по которому приложение проверяет, что
     подключилось именно к вашей базе. Aiven принимает подключения только по SSL.

Строку и сертификат никуда не коммитьте. Таблицы создавать вручную не нужно:
их создаст `start.sh` при первом запуске.

## Шаг 2. Сервис в Render

1. Убедитесь, что код с `render.yaml` уже отправлен на GitHub
   (в ту ветку, которую будете разворачивать).
2. Зайдите на https://render.com и зарегистрируйтесь через GitHub.
3. **New +** → **Blueprint** → выберите репозиторий (если его нет в списке —
   **Configure account** и дайте Render доступ к нему). Выберите ветку.
4. Render прочитает `render.yaml` и покажет сервис `vinland`. Он попросит
   два значения:
   - `DATABASE_URL` — Service URI из Aiven;
   - `DB_SSL_CA` — откройте `ca.pem` в Блокноте, выделите **весь** текст
     (от `-----BEGIN CERTIFICATE-----` до `-----END CERTIFICATE-----`) и
     вставьте в поле как есть, вместе с переносами строк. Render хранит
     многострочные значения.

   Если эти поля не появились, добавьте их после создания: сервис →
   **Environment** → **+ Add Environment Variable**, затем **Save and deploy**.

5. Нажмите **Deploy Blueprint** (или **Apply**).
6. Подождите. Первая сборка идёт 5–10 минут: ставятся пакеты Node, собирается
   интерфейс, собирается PHP-расширение `pdo_mysql`. Ход сборки видно во
   вкладке **Logs**. Успех выглядит так:

   ```
   Applied 001-schema.sql
   ...
   Demo account: demo@vinland.local / VinlandDemo2026
   PHP 8.4... Development Server (http://0.0.0.0:10000) started
   ```

7. Откройте адрес сервиса вида `https://vinland-xxxx.onrender.com` (он указан
   вверху страницы сервиса) и войдите:
   - email: `demo@vinland.local`
   - пароль: `VinlandDemo2026`

После этого каждый `git push` в эту ветку пересобирает и перезапускает сайт сам.

## Что значит «бесплатный план»

- **Сервис засыпает**, если 15 минут никто не заходил. Следующее открытие
  будит его, и это занимает **около минуты** — Render в это время показывает
  страницу загрузки. Перед показом преподавателю откройте сайт заранее.
- Бесплатных часов хватает, чтобы сайт работал весь месяц (750 часов).
- **База Aiven** сама не засыпает, но если ей долго никто не пользуется,
  Aiven может её **выключить** (power off). Перед этим приходит письмо на
  почту. То же бывает, если базой не воспользовались в первые часы после
  создания, поэтому делайте шаг 2 сразу после шага 1. Выключенную базу
  можно включить в любой момент: откройте сервис в консоли Aiven и нажмите
  **Power on**, через несколько минут он снова **Running**.
  Пока база выключена, сайт на Render не запустится — в логах будет ошибка
  подключения к базе. Пока демо открывают хотя бы иногда, база работает.
- Бесплатная база Aiven: 1 CPU, 1 ГБ памяти, **1 ГБ диска**, до 76
  подключений, одна бесплатная база MySQL на аккаунт, без SLA и поддержки.
  Для демо этого с большим запасом.

## Как устроен запуск

- **Миграции.** `php database/migrate.php` выполняет только новые файлы
  `database/*.sql`, поэтому каждый перезапуск безопасен.
- **Демо-аккаунт.** В `render.yaml` стоит `RESET_DEMO=1`: при каждом запуске
  (а значит, и после каждого «засыпания») демо-аккаунт создаётся заново с
  данными за последние три недели. Всё, что посетители изменили в демо,
  сбрасывается — для показа это удобно. Другие зарегистрированные пользователи
  не трогаются. Если сбрасывать не нужно, поменяйте `RESET_DEMO` на `0` в
  **Environment**: тогда демо создаётся только один раз, если его ещё нет.
- **HTTPS и сессия.** HTTPS обеспечивает Render. Cookie сессии отправляется
  с флагом `Secure` (`SESSION_SECURE=1`), браузер видит сайт по `https://`,
  поэтому вход работает.
- **Лимит попыток входа.** Перед приложением у Render стоит прокси, и
  `REMOTE_ADDR` у всех запросов одинаковый. Поэтому включён `TRUST_PROXY=1`:
  адрес посетителя берётся из заголовка `X-Forwarded-For`. Локально этот
  флаг не нужен.
- **Веб-сервер.** Используется встроенный сервер PHP (`php -S`) в 4 процесса
  (`PHP_CLI_SERVER_WORKERS=4`) — тот же, что и при локальном запуске. Для
  учебного демо этого достаточно; для настоящей нагрузки нужен nginx или Apache.
- **Настройки базы.** `backend/database.php` берёт `DATABASE_URL`, если она
  задана, иначе — `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`
  из окружения или `.env`. Параметр `?ssl-mode=REQUIRED` в конце строки
  приложение не читает: SSL включается, когда задан `DB_SSL_CA`.
- **Сертификат.** `DB_SSL_CA` может быть самим текстом сертификата (так
  удобнее на Render) или путём к файлу `ca.pem` (так удобнее на своём
  компьютере). Текст приложение сохраняет во временный файл, потому что PDO
  принимает только путь. С сертификатом PHP проверяет и сертификат, и имя
  сервера, поэтому подключиться к чужому серверу вместо базы нельзя.

## Если что-то пошло не так

- **Сборка пишет, что не найден Dockerfile.** Откройте сервис → **Settings** →
  **Build & Deploy** и проверьте: Root Directory = `app`, Dockerfile Path =
  `./Dockerfile` (или `app/Dockerfile`, если Render считает путь от корня репозитория).
- **В логах ошибка подключения к базе.** Сначала проверьте в консоли Aiven,
  что база в статусе **Running**, а не выключена. Потом проверьте
  `DATABASE_URL` в **Environment**: строка целиком, начинается с `mysql://`,
  без пробелов.
- **`Cannot connect to MySQL using SSL` или ошибка про сертификат.** В
  `DB_SSL_CA` вставлен не весь `ca.pem` или пропали переносы строк. Вставьте
  текст файла заново, целиком.
- **«Слишком много попыток» при входе в демо.** Кто-то 5 раз подряд ввёл
  неверный пароль от демо-аккаунта. Это защита от перебора: подождите 15 минут.
- **Нужен администратор.** На бесплатном плане нет консоли Render, но команду
  можно выполнить со своего компьютера (в PHP должно быть включено
  расширение `pdo_mysql`), подключившись к той же базе Aiven. Здесь
  `DB_SSL_CA` — путь к скачанному файлу:

  ```powershell
  cd app
  $env:DATABASE_URL = 'Service URI из Aiven'
  $env:DB_SSL_CA = 'C:\Users\вы\Downloads\ca.pem'
  php database/create-admin.php admin@example.com "пароль-от-10-символов"
  ```

## Проверить Docker-образ у себя (необязательно)

```bash
cd app
docker build -t vinland .
docker run --rm -p 8080:8080 -e DATABASE_URL='Service URI из Aiven' -e DB_SSL_CA="$(cat ca.pem)" vinland
```

Откройте http://localhost:8080. Если вход не сохраняется (cookie помечена
`Secure`, а здесь нет HTTPS), добавьте к команде `-e SESSION_SECURE=0`.
