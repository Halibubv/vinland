# Путеводитель по коду

Короткое объяснение, как устроено приложение и где что искать. Удобно
перечитать перед защитой.

## Три части

1. **Интерфейс** (`src/`) — React. Рисует экраны и отправляет запросы на сервер.
   После `pnpm run build` превращается в обычные HTML, JS и CSS в `public/ui`.
2. **Сервер** (`public/index.php` и `backend/`) — PHP без фреймворка.
   Принимает запросы `/api/...`, проверяет данные, работает с базой и отвечает JSON.
3. **База** (`database/`) — MySQL 8. Таблицы описаны в SQL-файлах `001`–`005`,
   их по порядку выполняет `migrate.php`. Все таблицы — InnoDB (без него не
   работают внешние ключи и транзакции) в кодировке utf8mb4.

## Путь одного действия: «Сохранить приём пищи»

1. Пользователь нажимает «Сохранить в дневник» на экране
   `src/pages/MealEditor.jsx`. Срабатывает функция `save`: она проверяет, что
   продукты есть и граммы больше нуля, и собирает объект с датой, типом и продуктами.
2. `save` вызывает `api('/meals', 'POST', body)` из `src/api.js`.
   Эта функция делает `fetch` на `/api/meals` и превращает ответ сервера
   в объект или в понятную ошибку.
3. Запрос приходит в `public/index.php`. Это таблица маршрутов: метод + адрес →
   функция. Для `POST /api/meals` вызываются:
   - `require_user()` (`backend/auth.php`) — кто вошёл; если никто, ответ 401;
   - `read_json()` (`backend/http.php`) — читает тело запроса;
   - `save_meal()` (`backend/meals.php`) — сначала проверяет поля через функции из
     `backend/validation.php` (при ошибке ответ 422 с текстом для пользователя),
     потом в одной транзакции сохраняет приём пищи и продукты.
     Вместе с продуктом записываются его название и КБЖУ на этот день (снимок),
     чтобы правка справочника не меняла старые записи.
4. `respond()` отправляет JSON с сохранённым приёмом пищи. Интерфейс получает
   ответ и переходит обратно в дневник: `navigate(...)` из React Router.

Остальные действия (тренировки, профиль, справочники админа) устроены так же:
экран → `api()` → маршрут в `index.php` → функция в `backend/` → база → JSON.

## Как устроен PHP

Весь сервер — это обычные функции без классов и фреймворков. Каждый файл в
`backend/` отвечает за одну тему.

| Файл | Что внутри |
| --- | --- |
| `public/index.php` | Список маршрутов: `if ($method === 'POST' && $path === '/api/meals') { ... }`. Каждый маршрут вызывает функцию из `backend/` и отправляет ответ через `respond()`. |
| `backend/bootstrap.php` | Подключает все файлы (`require`), запускает сессию (`session_start`), задаёт ответ на непредвиденную ошибку. |
| `backend/config.php` | `config('DB_HOST')` — настройка из переменных окружения или файла `.env`. |
| `backend/database.php` | Подключение к MySQL через PDO, `query($sql, $values)` и `insert(...)`. |
| `backend/http.php` | `respond($data)` — отправить JSON, `send_error(404, 'текст')` — отправить ошибку, `read_json()` — прочитать данные формы. |
| `backend/validation.php` | Проверка полей: `text_value`, `number_value`, `date_value`, `email_value` и т. д. При ошибке — ответ 422 и текст для поля. |
| `backend/auth.php` | `register`, `login`, `logout`, `current_user`, `require_user`, `require_admin`. |
| `backend/profile.php`, `catalog.php`, `admin.php`, `workouts.php`, `meals.php`, `statistics.php` | CRUD по своим таблицам. |

**Как работает вход.** При входе PHP проверяет пароль (`password_verify`) и
кладёт id пользователя в сессию: `$_SESSION['user_id'] = ...`. Сессия хранится
на сервере, а браузер получает только её номер в cookie. При следующих запросах
`current_user()` берёт id из сессии и читает пользователя из базы.

**Роли.** Гость — нет `$_SESSION['user_id']`, любой адрес API кроме входа и
регистрации отвечает 401. Пользователь — `role = 'user'`. Администратор —
`role = 'admin'`, только ему открыты адреса `/api/admin/...` (`require_admin()`).

**Что сложнее обычного CRUD** (стоит знать, как объяснить):

- **Снимок КБЖУ** (`meals.php`). При добавлении продукта в приём пищи его
  название и КБЖУ копируются в `meal_items`. Если админ потом поменяет продукт,
  старые записи дневника не изменятся. КБЖУ приёма пищи = граммы × значение на
  100 г ÷ 100 (`meal_totals`).
- **Правка тренировки или приёма пищи** (`save_workout`, `save_meal`). Сначала
  проверяем все данные, потом в транзакции удаляем старый список упражнений
  (или продуктов) и записываем новый целиком. Так проще, чем искать, что
  изменилось.
- **Статистика** (`statistics.php`). Два SQL-запроса с `SUM`/`COUNT` и
  `GROUP BY` дают итоги по дням, потом PHP раскладывает их по всем дням периода,
  чтобы на графике не было пропусков.
- **Аватар** (`profile.php`). Браузер сам уменьшает фото и присылает строку
  `data:image/jpeg;base64,...`. Сервер проверяет начало строки и размер и
  сохраняет её в поле `users.avatar`. Эта же строка потом стоит в `<img src>`.
- **Админка** (`admin.php`). Панель: `COUNT(*)` по таблицам и список
  пользователей (сменить роль, удалить вместе с записями). Фото записи
  справочника браузер присылает строкой base64, сервер раскодирует её
  (`base64_decode`) и сохраняет файлом в `public/assets/catalog/uploads`, а в
  поле `image` пишет имя файла.
- **SSL для облачной базы** (`database.php`, `ssl_certificate_file`). Нужно
  только для демо в интернете (Render + Aiven): облачная база пускает лишь по
  защищённому соединению. На своём компьютере не используется.

## Что из React здесь используется

- **Компонент** — функция, которая возвращает разметку (JSX). Каждый экран в
  `src/pages/` — компонент.
- **`useState`** — данные экрана, которые меняются: введённый текст, загруженный
  список, текст ошибки. После `setЧто-то(...)` React перерисовывает экран.
- **`useEffect`** — код, который выполняется после показа экрана. Здесь он почти
  всегда загружает данные с сервера.
- **props** — параметры, которые компонент получает от родителя, например
  `<AdminCatalog kind="products" />` или `<DayTotals day={...} goals={...} />`.
- **React Router** — переходы между страницами без перезагрузки:
  - `<BrowserRouter>` в `src/main.jsx` следит за адресом в браузере;
  - `<Routes>` и `<Route path="..." element={...} />` в `src/App.jsx` — какой
    экран показать по какому адресу;
  - `<Link to="/workouts">` — ссылка внутри приложения (вместо `<a href>`);
  - `useParams()` — достаёт часть адреса: на `/workouts/:id` это `id` тренировки
    (`WorkoutView.jsx`, `WorkoutEditor.jsx`, `MealEditor.jsx`), а на
    `/nutrition/day/:date` — выбранный день дневника (`Nutrition.jsx`);
  - `useNavigate()` — перейти на другую страницу из кода, например после сохранения;
  - `useLocation()` — текущий адрес: по нему подсвечивается пункт меню
    (`Layout.jsx`), а `App.jsx` прокручивает новую страницу в начало.
- **Фильтры** — `массив.filter(...)`: тренировки выбранного месяца и дня
  (`Workouts.jsx`), поиск и кнопки групп мышц в окне выбора (`Dialogs.jsx`),
  приёмы пищи по типу (`Nutrition.jsx`), дни с тренировками и дни «в норме
  калорий» (`Statistics.jsx`).

| Практика | Пример попроще | Пример посложнее |

нет специально, чтобы код можно было прочитать без лишних знаний.

### Что лежит в `src/`

- `main.jsx` — точка входа: подключает стили и запускает `<App />` внутри `<BrowserRouter>`.
- `App.jsx` — главный компонент: спрашивает сервер, кто вошёл, и по адресу выбирает экран.
- `api.js` — одна функция `api(адрес, метод, данные)`: отправляет запрос на сервер
  и возвращает ответ. Плюс `errorText` — собрать текст ошибки для формы.
- `format.js` — как показывать данные: даты («16 ноября», «Сегодня»), числа
  («2 400»), слова в нужном падеже («3 подхода») и названия приёмов пищи.
- `image.js` — уменьшает выбранное фото до квадрата прямо в браузере перед отправкой.
- `components/Layout.jsx` — шапка с меню, нижнее меню на телефоне, подвал, логотип, аватар.
- `components/ui.jsx` — мелкие детали, нужные на нескольких экранах: поле формы,
  каркас страницы, сообщение об ошибке, пустой список, выбор даты, фото записи.
- `components/Dialogs.jsx` — всплывающие окна: выбор из справочника и «Удалить?».
- `components/OwnItemDialogs.jsx` — окна «Своё упражнение» и «Свой продукт».
- `components/DayTotals.jsx` — кольцо калорий и полоски белков, жиров и углеводов.
- `components/PageHero.jsx` — большой баннер с фото вверху тренировки, питания и профиля.
- `components/RiseText.jsx`, `CountUp.jsx`, `HeroSnow.jsx` — анимации: буквы
  заголовка всплывают, число калорий досчитывает, на главной падает снег.
- `pages/*.jsx` — экраны, по одному на файл; рядом лежит `.css` с их стилями.
- `styles.css`, `styles/*.css` — общие стили, размеры экранов и анимации.

## Безопасность в двух словах

- Пароли хранятся только в виде хеша (`password_hash`).
- Cookie сессии с `HttpOnly` (недоступна JavaScript) и `SameSite=Lax`
  (браузер не отправит её с запросом на изменение данных с чужого сайта).
- Сервер всегда проверяет, что тренировка или приём пищи принадлежит
  пользователю, который их запрашивает.
- Данные от пользователя попадают в SQL только как параметры подготовленного
  запроса (`query($sql, $parameters)`), поэтому SQL-инъекция через них не пройдёт.

## Что из MySQL здесь используется

- **`AUTO_INCREMENT`** — id новой строки база выдаёт сама. Узнать его сразу
  после `INSERT` помогает `insert()`: она вызывает `PDO::lastInsertId()`.
- **Внешние ключи** (`FOREIGN KEY`) — например, подход нельзя сохранить без
  тренировки, а при удалении тренировки удаляются и её подходы.
- **`CHECK`** — база сама не пустит, например, продукт на 0 граммов (`quantity_g > 0`).
- **Транзакции** — тренировка со всеми упражнениями и подходами сохраняется
  целиком или не сохраняется вовсе (`beginTransaction` / `commit` /
  `rollBack` в PDO).
- **Логические поля** (`is_active`) хранятся как `1` или `0`. В ответе
  сервера они превращаются в `true` или `false` (`backend/admin.php`).
- **`NULL` как «общее»** — в `exercises` и `products` поле `user_id` пустое у
  общего справочника и заполнено у своей записи пользователя. Поэтому список
  выбирается условием `user_id IS NULL OR user_id = ?` (`backend/catalog.php`),
  а админка видит только `user_id IS NULL`.
- **`JOIN`** — склеить строки двух таблиц: упражнение тренировки + его название
  из справочника (`backend/workouts.php`).
- **`SUM`, `COUNT`, `GROUP BY`** — итоги по дням для статистики (`backend/statistics.php`).
