# ВИНЛАНД — состояние промежуточной версии

Дата проверки: 17 октября 2026 года. Это рабочий локальный срез, не финальная приёмка и не production-развёртывание. Точный Git-коммит поставки указан в `MANIFEST.md` комплекта.

## Реализовано

- React на JavaScript и CSS обслуживаются PHP-сервером из `public/`; production-сборка уже лежит в `public/ui/`. Node.js нужен только для разработки и новой сборки, не для запуска готового интерфейса.
- PHP API через PDO и PostgreSQL: миграции, серверная валидация, сессии, CSRF, регистрация, вход, выход, профиль и личные цели КБЖУ. Пароли хешируются; регистрация не выдаёт права администратора.
- Тренировки: создание, просмотр, правка, удаление, порядок упражнений, подходы, нулевой вес, заметки и история. Редактирование старой записи сохраняет ссылку на архивное упражнение; новая запись не может выбрать неактивное.
- Питание: справочник продуктов, приёмы пищи, граммовки, история, расчёт КБЖУ по сохранённым снимкам названия и нутриентов. Изменение или деактивация продукта не переписывает старые записи.
- Статистика за диапазон дат и административные справочники упражнений и продуктов с разграничением прав. Прямые URL рабочих экранов обслуживаются приложением; закрытые серверные файлы не выдаются публично.
- Интерфейс содержит состояния пустых данных и ошибок, адаптивные страницы, диалог выбора упражнения с поиском и клавиатурным управлением, черновики форм, привязанные к пользователю.

## Подтверждено проверками

- Production-сборка Vite успешна; PHP lint для `public/index.php` успешен; `tests/unit.php` — 16 проверок.
- `tests/run-ui-browser.ps1` пройден в Chrome на отдельной тестовой БД и порту 8082: маршруты, приватные файлы, регистрация и вход, сохранение профиля после перезагрузки, CRUD тренировок и еды, порядок и пустые подходы, нулевой вес, исторические КБЖУ, права администратора и владение записями, черновики, ошибка сохранения и восстановление после истечения сессии.
- Скрипт также проверяет наличие используемых SVG-иконок и отсутствие горизонтального переполнения заполненных редакторов на 834 и 390 px. Его тестовая БД не является пользовательской БД `vinland`.

## Частично реализовано / требует полировки

- Основные экраны ориентированы на принятую Figma `WvVwCw5GygFJKVVLUejEwt`, но полное попиксельное соответствие на 1280/834/390 px ещё не подтверждено. Особенно требуют сверки редактор питания, статистика, admin-шапка и мобильные состояния.
- Для питания используется обычный HTML `select`, а подтверждение удаления — `window.confirm`; они работают, но не повторяют утверждённые кастомные состояния Figma.
- Статистический график пока использует минимальную видимую высоту даже при нулевых калориях; настоящая линия цели и сетка графика не реализованы. Не считайте легенду линии подтверждением её отображения.
- Часть фотографий в карточках питания пока общая, а не связана с конкретным продуктом. Для произвольных упражнений используется нейтральный значок вместо вымышленной фотографии.
- Google Fonts загружаются через интернет; при недоступности сети применяются системные запасные шрифты, поэтому типографика может отличаться.
- Анимации и `prefers-reduced-motion` заданы в CSS, но полный runtime-аудит всех состояний (туман, появление секций, прогресс, меню, диалоги) ещё не завершён.

## Не проверено в этой поставке

- Production-сервер с HTTPS, реальный хостинг, нагрузка, резервное копирование и поведение на других браузерах. Встроенный PHP-сервер — только для локального запуска.
- Полная визуальная приёмка каждого состояния Figma и ручная проверка всех длинных форм/модальных окон на физических устройствах.

Следующий шаг: завершить визуальную и motion-сверку по принятому макету, затем повторить сквозные проверки и провести отдельную production-подготовку. Не заменять данные пользователя демонстрационными записями.
