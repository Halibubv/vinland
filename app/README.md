# ВИНЛАНД: рабочее приложение

Стек: React (JavaScript), обычный CSS, PHP 8.4+, PostgreSQL 17+. Без PHP-фреймворка и ORM. Vite используется только для разработки и сборки интерфейса. Сайт пока в разработке: наличие серверного каркаса не означает готовность приложения.

## Запуск серверной части

1. Создайте PostgreSQL-пользователя и пустую БД `vinland` (UTF-8). Не используйте суперпользователя для обычных запросов приложения.
2. Скопируйте `.env.example` в `.env`, укажите локальные параметры БД. `.env` не добавляется в Git.
3. В PHP включите расширение `pdo_pgsql`.
4. Из папки `app`: `php database/migrate.php`.
5. Для локальной разработки: `php -S 127.0.0.1:8081 -t public router.php`.

В production нужны HTTPS, `SESSION_SECURE=1`, настроенный веб-сервер с document root строго `app/public`. Встроенный сервер PHP предназначен для локальной разработки.

Проверки: `php tests/unit.php`, затем при запущенном сервере `node tests/http.mjs` и `node tests/auth.mjs`. Проверка `/api/health` обращается к реальной БД, а `/api/session` выдаёт текущего пользователя и CSRF-токен. Второй HTTP-тест создаёт локального тестового пользователя и проверяет регистрацию, профиль, выход, вход и ограничение неверных попыток. Для тренировок сначала выполните `php tests/seed-workout-exercises.php`, передайте выведенные ID через `TEST_EXERCISE_IDS`, затем запустите `node tests/workouts.mjs`; `php tests/workout-history.php` проверяет правку уже сохранённой тренировки после деактивации упражнения. На Windows `tests/run-meals-http.ps1` создаёт отдельную тестовую БД и проверяет HTTP-сценарии питания, admin-справочников и статистики; локальные серверы после прогона останавливаются, тестовая БД остаётся для диагностики.

`GET /api/statistics?from=YYYY-MM-DD&to=YYYY-MM-DD` возвращает дни, итоги и цели текущего пользователя. Диапазон ограничен одним годом. `/api/admin/exercises` и `/api/admin/products` доступны только администратору: `GET` — полный справочник, `POST` — новая запись, `PUT /:id` — полная правка, в том числе `is_active`. Неактивные записи остаются в истории и не предлагаются для новых записей пользователя.

## Интерфейс (в разработке)

Из папки `app` установите зависимости `pnpm install` и выполните `pnpm run build` (или `node node_modules/vite/bin/vite.js build`, если системный `pnpm` недоступен). Собранный React-интерфейс обслуживается тем же PHP-сервером по `http://127.0.0.1:8081/`. Прямые адреса страниц входа, профиля, тренировок, питания, статистики и справочников администратора тоже открываются. Эти разделы подключены к API: тренировки и приёмы пищи можно создавать, менять и удалять; неактивные записи справочника не пропадают из истории. Визуальная доводка форм и адаптивных состояний продолжается. Для разработки без сборки можно запустить Vite, но при проверке релизного пути используйте именно PHP-сервер и сборку.

На Windows `tests/run-ui-browser.ps1` создаёт отдельную тестовую БД и проверяет маршруты, авторизацию, UI CRUD, исторические КБЖУ, права доступа, черновики и адаптивные формы в Chrome. Скрипт запускает свой PHP-сервер на свободном порту 8082 и останавливает его после проверки; обычный предпросмотр на 8081 остаётся доступным. Перед первым запуском установите Python Playwright в `app/.test-deps`: `python -m pip install --target .test-deps playwright`. Скриншоты остаются локально в `app/.screenshots`, в Git не входят.

## Как устроен код

`public/index.php` принимает API-запросы. `backend/bootstrap.php` подключает функции, запускает защищённую сессию и общий обработчик ошибок. `database.php` создаёт PDO-соединение; `validation.php` проверяет данные. `database/*.sql` — последовательные миграции; их выполнение отмечается в таблице `migrations`, повторный запуск не стирает данные.

Менять данные можно только с CSRF-токеном из `/api/session`, переданным заголовком `X-CSRF-Token`. Пароль и роль пользователя не доверяются браузеру. Детали внутренних ошибок записываются только в журнал сервера.
